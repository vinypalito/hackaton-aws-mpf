# Padrões de Documentação e Specs

Este documento define como a documentação e os specs devem ser produzidos neste
projeto.

## Idioma

- **Toda a documentação deve ser escrita em português do Brasil.**
- **Todos os specs** (requisitos, design e tarefas) **devem ser escritos em
  português.**
- Textos devem ser claros, objetivos e revisados quanto a ortografia e gramática.

## Documentação

- Mantenha os arquivos de steering (`product.md`, `tech.md`, `structure.md`)
  atualizados conforme o projeto evolui.
- README e documentos de apoio devem explicar: propósito, como instalar, como
  executar e como testar.
- Prefira exemplos práticos e trechos de código funcionais.

## Specs

Os specs seguem o fluxo estruturado do Kiro, sempre em português:

1. **Requisitos** — o que precisa ser construído, com critérios de aceitação
   claros e verificáveis.
2. **Design** — como será construído: arquitetura, componentes, fluxos de dados
   e decisões técnicas.
3. **Tarefas** — passos incrementais de implementação, cada um rastreável até os
   requisitos.

Diretrizes:

- Cada requisito deve ter critérios de aceitação testáveis.
- O design deve referenciar os requisitos que atende.
- As tarefas devem ser pequenas, independentes e verificáveis.

## Estilo de Escrita

- Use voz ativa e frases curtas.
- Evite jargões desnecessários; quando usar termos técnicos, mantenha-os
  consistentes com o glossário em `product.md`.
- Estruture documentos longos com títulos e listas para facilitar a leitura.
